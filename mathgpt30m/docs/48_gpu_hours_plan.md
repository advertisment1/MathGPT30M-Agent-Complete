# 60M 数学 GPT：48 GPU-hours 实验协议

> 单张 GPU 上的 48 小时硬上限如何切分，以及本次执行的实测耗时。正式模型 60M，训练量 6 亿 token。

## 决策

- 正式模型：**60M**（实测 59,612,640 参数，偏差 0.65%）；训练量 6 亿 token（10 token/参数）。
- 理论研究：同架构家族训练 3 个代理规模（4.83M / 8.58M / 14.09M）× 3 档 token 预算，共 9 点，每点一个 seed；用 SciPy least_squares 拟合 E,A,B,alpha,beta。
- 数据：同一 tokenizer、冻结验证集、相同数学数据来源和优化器设置；各训练预算必须准确记录实际消耗的 token 数。

## 时间：上限 vs 实测（单 GPU，非多 GPU 相加）

| 任务 | 上限小时 | 实测小时 |
|---|---:|---:|
| 部署 / 数据 / 正确性验证 | 4 | ~0.8（装 torch、200k docs 流式打包、pytest、50 步试跑） |
| 六轮消融 | 6 | ~0.5（3 seed × 1000 步 × 六轮） |
| 代理 scaling 网格 | 8 | **~10.7**（每模型 10×/20×/40× 参数量，共 1.93B token） |
| 60M 正式预训练 | 26 | **4.67**（18,311 步 × 32,768 token，日志 `elapsed_step_s` 求和） |
| 评估、修复、缓冲 | 4 | ~0.6（生成样例、曲线、scp、三次停机重连） |
| **合计** | **48** | **~17** |

> Scaling 网格实耗 10.7 h，超出 8 h 的分配额：9 个点按每模型 10×/20×/40× 参数量共 19.3 亿 token，由 `--max_hours 14` 兜底跑完，未截断任何点。
> 48 h 是**硬上限**，不是预期用时的承诺。

## 执行与决策门槛

1. 先用 10–20 分钟跑目标模型，测 tokens/s、峰值显存和 validation loss，估算可完成 token 数（60M 实测 4.1–4.7 万 tok/s）。
2. **Scaling**：每档模型训 10×/20×/40× 参数量的 token；耗时超过 8h 就停，不虚构缺失点。
3. 使用相同 held-out validation 文本和 tokenizer；训练 token 预算 D 指累计被模型看过的 token（重复采样要记录），不能等同唯一 token 数。
4. 模型族固定层宽比、头维、GQA 比率等结构规则；实际参数量以模型统计为准。
5. 记录每次 N、D、val loss、seed、硬件、tokens/s、训练时长、配置 hash。
6. 拟合 `L(N,D)=E+A(N/1e6)^(-alpha)+B(D/1e6)^(-beta)`，并报告 RMSE、残差、外推风险；仅 9 点拟合 5 参数很脆弱（本次 RMSE=0.043、α=0.652、β=1.010）。
7. 预算 C_flops 需用实际吞吐测算，不能把 48 GPU-hours 当作 FLOPs；通过 `C≈6ND` 求 N*、D*，此近似忽略注意力二次项（本次 C=2.16e17 → N*=138.9M，仅理论参考）。
8. 正式训练优先：如数据预处理或网格超时，压缩代理实验而不是取消正式训练。
9. WSD：线性 warmup、stable、线性 decay；在正式训练开始前根据预计 steps 设置，预留尾部 decay（本次 warmup 915 / decay 1831 / 峰值 lr 3e-4）。
10. 后训练 SFT 不在本轮 48h 基线交付中；先评估预训练模型的困惑度、生成能力，再考虑数学题解 SFT。
